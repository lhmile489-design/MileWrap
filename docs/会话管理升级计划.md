# 会话管理（历史记录）升级计划

> 日期：2026-11-01
> 目标：在 Mile Warp 里管理本机 agent 的历史会话。按目录归类，可以查看、搜索、续接、改名、删除、导出。
> 依据：2026-11-01 对本机四个 agent 真实存储的实测（见 §2），不是按文档推测。
> 状态：P0、P1、P2 已完成（只读：列表、搜索、预览、续接、导出）；P3 以后（改名、删除）未开工，等 §9 拍板。进度与实测见 §10。

---

## 1. 结论：难度评估

**总体难度：中高。工期约 11 到 14 个工作日，其中只读版（列表、搜索、预览、续接、导出）约 6 到 7 天。**

难点不在界面，在两处：

1. **四个 agent 的历史存储格式各不相同，而且都是第三方私有格式。** Claude 是 jsonl，Codex 是 jsonl 加 sqlite 索引，Kimi 是目录加 `state.json`，Pi 是 jsonl。它们随时可能改版本，我们没有任何兼容保证。
2. **写操作（改名、删除）是在改别人的数据。** 这和项目现有的一条原则冲突：`ResumeDiscovery` 的约定是「只读这些文件，不改不删」。删错了没法恢复，改坏了 agent 自己会打不开会话。

| 操作 | Claude | Codex | Kimi | Pi |
| --- | --- | --- | --- | --- |
| 列表 / 按目录归类 | 易 | 易（有 sqlite 索引） | 易 | 易 |
| 搜索标题 / 首条消息 | 中（要读文件头尾） | 易（索引里有字段） | 易（`state.json`） | 中 |
| 预览对话 | 中 | 中 | 中 | 中 |
| 导出 | 易 | 易 | 易 | 易 |
| 改名 | 易（追加一行） | 难（要写 sqlite） | 易（改 `state.json`） | 不确定（没找到标题字段） |
| 删除 | 中（附属文件多） | 难（文件加数据库多张表） | 易（删目录加索引行） | 易（删一个文件） |

最容易的一半（读、导出）风险低、价值高，建议先做。写操作分批、加保护，Codex 的写操作放最后，用户同意后再做（§9 问题 2）。

## 2. 本机四个 agent 的存储实测

以下全部来自本机真实数据。标「待核」的是还没验证的，P0 阶段要先验证。

### 2.1 Claude Code

- **位置**：`~/.claude/projects/<目录编码>/<sessionId>.jsonl`。目录编码是把工作目录里的非字母数字字符换成 `-`，例如 `E--WebApp-szpu-takeout-szpu-takeout-webapp`。这个编码不可逆，**目录要从文件内每行的 `cwd` 字段读，不能从目录名反推**。
- **内容**：每行一个 JSON，`type` 有 `user`、`assistant`、`system`、`attachment`、`queue-operation`、`custom-title`、`agent-name`、`last-prompt`、`file-history-snapshot`、`cost-state` 等十多种。消息靠 `parentUuid` 串成链。
- **标题**：没有独立的索引文件。用户改过名的会话，文件里有 `custom-title` 和 `agent-name` 行，取最后一条。没改过名的要用首条用户消息顶替。
- **附属数据**：同名子目录 `<sessionId>/subagents/`。另外 `~/.claude/` 下有 `file-history`、`todos`、`session-env`、`shell-snapshots`、`tasks`、`plans`、`sessions`、`debug`，部分按 sessionId 命名。**这些是否确实按 sessionId 对应，实测时没有匹配上，待核**，决定删除要不要连带清理。
- **全局输入历史**：`~/.claude/history.jsonl`（约 770KB），每行有 `display`、`project`、`sessionId`，是上下键翻出来的历史，不是会话本体。
- **续接**：`claude --resume <sessionId>`，项目已支持。

### 2.2 Codex CLI

- **位置**：`~/.codex/sessions/YYYY/MM/DD/rollout-<时间>-<threadId>.jsonl`。已归档的在 `~/.codex/archived_sessions/`。
- **索引**：`~/.codex/state_5.sqlite` 的 `threads` 表，本机有 1279 行，其中 42 行 `archived=1`。字段很全：`id`、`title`、`name`（用户改的名字）、`cwd`、`rollout_path`、`first_user_message`、`git_branch`、`archived`、`created_at_ms`、`updated_at_ms`、`is_pinned` 等。旁边还有 `thread_attachments`、`thread_dynamic_tools`、`thread_spawn_edges` 等关联表。
- **坑**：`cwd` 和 `rollout_path` 带 `\\?\` 前缀；rollout 文件数（1241）和线程数（1279）对不上，索引里有记录没有文件（或文件在归档目录），列表要容忍缺文件。
- **读库**：Electron 43 自带 Node 24.18，实测 `node:sqlite` 可以直接用，**不需要新增 npm 依赖**，也不用重编原生模块。
- **续接**：`codex resume <threadId>`，项目已支持。

### 2.3 Kimi Code

- **位置**：`~/.kimi-code/sessions/wd_<目录名>_<哈希>/session_<uuid>/`。
- **每个会话一个目录**：`state.json`（`title`、`isCustomTitle`、`createdAt`、`updatedAt`、`workDir`、`lastPrompt`）、`main/wire.jsonl`（对话本体，约 486KB）、`logs/`、`agents/`。
- **目录映射**：`~/.kimi-code/workspaces.json` 把 `wd_*` 对应到真实目录，`session_index.jsonl` 是所有会话的平铺索引（项目的续接 ID 发现已经在读它）。
- **其他**：`user-history/*.jsonl` 是输入历史。
- **续接**：`kimi --session <id>`，项目已支持。

### 2.4 Pi

- **位置**：`~/.pi/agent/sessions/--<目录编码>--/<时间>_<uuid>.jsonl`，本机只有 4 个文件。
- **内容**：首行是 `{"type":"session","version":3,"id":...,"cwd":...}`，之后是 `message`、`model_change`、`thinking_level_change`、`context_edit` 等。
- **标题**：没有找到标题字段（待核；`pi --name` 设的名字可能存在别处）。先用首条用户消息顶替。
- **续接**：`pi --session-id <uuid>`，项目已支持。

### 2.5 规模

Claude 约 300 多个会话文件（待核）、Codex 1279 个线程、Kimi 约 29 个、Pi 4 个。**最大单文件在 4MB 级（一个 Pi 会话 4.1MB）。** 所以列表绝不能整个解析所有文件，要读文件头尾，并按「修改时间加大小」缓存。

## 3. 设计

### 3.1 架构：每个 agent 一个适配器

主进程新增 `SessionHistoryService`，下面挂四个适配器，统一接口：

```
list()                      → HistoryItem[]    不含对话正文
detail(id, range)           → 分页的消息       预览用，不整个读进内存
rename(id, title)           → void
remove(id)                  → void
export(id, format)          → 文本或原文件
```

`HistoryItem` 统一字段：`historyId`（不透明 ID）、`agentId`、`sessionId`（续接 ID）、`cwd`（规范化后的目录）、`title`、`firstMessage`、`createdAt`、`updatedAt`、`size`、`messageCount`、`gitBranch`、`running`（是否正被 Warp 里的会话占用）。

目录规范化要统一处理：反斜杠与斜杠、盘符大小写、Codex 的 `\\?\` 前缀。归属到工作区用现有的 `samePath()`。不属于任何工作区的目录单独列在「其他目录」里，因为很多会话是你在 Warp 外面开的。

### 3.2 安全模型（沿用项目硬规则）

- **渲染层不经手任何路径。** 渲染层只拿 `historyId`，由主进程在每次 `list` 时生成并保存「ID 到路径」的映射。不接受渲染层传来的文件路径，请求里的 ID 找不到就拒绝。
- 所有路径必须落在固定根目录下（四个 agent 各自的目录，开发期可用 `MILE_WARP_AGENT_HOME` 指到沙箱），操作前 `realpath` 校验，越界拒绝。
- 新增 IPC 照 CLAUDE.md 的规则，四处同时改：`shared/channels.ts`、主进程 `sanitize*`、preload 白名单、`index.d.ts`。预计 6 个频道：`history:list`、`history:detail`、`history:rename`、`history:remove`、`history:export`、`history:open`（续接）。
- **导出保存**走主进程弹系统保存对话框，渲染层只拿成功或取消。

### 3.3 写操作的保护

1. **正在使用的会话不能动。** 会话的续接 ID 如果在 Warp 的运行中会话里（现有 `liveResumeIds`），拒绝改名和删除。Warp 外面正在跑的同一个会话检测不到，删除前的确认框要写明这一点。
2. **删除走回收站**（`shell.trashItem`），不做永久删除。删错了能从回收站拿回来。
3. **删除前要确认**，批量删除要列出条数和目录。
4. **写之前先备份被改的小文件**（`state.json`、sqlite 之外的索引行），放到 Warp 自己的数据目录，保留 7 天。
5. **改名尽量不改别人的文件。** 增加一个 Warp 自己的「别名层」`history-meta.json`（标题覆盖、备注、标签）。能安全写回 agent 的（Claude 追加一行、Kimi 改 `state.json`），写回并同步别名；写回风险大的（Codex、不确定的 Pi），只写别名层，列表里显示别名，并标「仅 Warp 内可见」。
6. **Codex 的任何写操作**：先检查数据库能否拿到写锁（`BEGIN IMMEDIATE`，带超时），拿不到就提示「Codex 正在使用，请先退出」，不重试强写。

### 3.4 与 Warp 自己的数据联动

- 删除某个会话后，`config.sessionRecords` 里引用同一个续接 ID 的记录要一起清掉，否则「一键恢复」会续接一个不存在的对话。
- 历史里的「续接」直接复用现有的 `session:resumeWorkspace` 路径，不另写启动逻辑。从历史续接到指定格子，复用 `place()`。
- 刚在 Warp 里新开的会话，文件可能还没写出来，列表要容忍「有记录无文件」。

### 3.5 界面

建议做成一个大的「会话历史」对话框，不新增常驻栏位（四宫格已经很挤）：

- **左**：目录列表。先是已有工作区，再是「其他目录」。每项显示会话数。
- **中**：该目录下的会话列表，四个 agent 混排，按更新时间倒序。每行：agent 图标、标题、首条消息摘要、时间、大小。顶部是搜索框（标题加首条消息）和 agent 筛选。
- **右**：预览。分页加载消息，默认折叠工具调用和思考内容。
- **操作**：续接到当前格、改名、删除、导出、复制会话 ID、在资源管理器中显示。多选后批量删除和导出。
- **入口**：工作区右键菜单「历史会话…」（自动定位到该目录）、标题栏按钮、命令面板。

界面遵守现有约束：Phosphor 图标、状态不只靠颜色、文字不加透明度、不引入组件库和虚拟滚动库（列表分批渲染，参考目录栏每批 300 项）。

### 3.6 导出

| 格式 | 内容 | 用途 |
| --- | --- | --- |
| Markdown | 标题、目录、时间，按轮次的用户 / assistant 文本，工具调用折叠为摘要 | 阅读、归档、贴给别人 |
| JSON | 统一结构的消息数组加元数据 | 二次处理 |
| 原始文件 | 原样复制 jsonl（Kimi 打成 zip 目录太重，导出 `wire.jsonl` 加 `state.json`） | 备份、迁移 |

导出的 Markdown 默认不含思考内容和工具的大段输出，在导出对话框里可勾选。

## 4. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| agent 升级后格式变化 | 列表解析失败或数据读错 | 每个适配器独立，解析失败只让该条显示「无法解析」，不影响整体；版本号记入日志；每个格式留 fixture 测试 |
| 误删正在用的会话 | 对话丢失 | 运行中检测加回收站加确认；Codex 要拿写锁 |
| 写坏 Codex 数据库 | Codex 自己打不开 | Codex 写操作放最后，需你同意；事务内操作，失败整体回滚；先备份 |
| 大文件拖慢列表 | 打开历史页卡顿 | 只读头尾、按 mtime 加 size 缓存、后台线程式分批（主进程异步分片，不阻塞 IPC） |
| 隐私 | 会话里有密钥、代码 | 导出前提示；日志只记频道名和条数，不记内容（沿用现有日志约束） |
| 目录规范化出错 | 会话归错工作区 | 统一一个规范化函数，加 `\\?\`、斜杠、盘符大小写的用例 |

## 6. 验证

沿用项目的真实进程 harness 纪律，不引入单元测试框架：

- 新增 `scripts/verify-history.cjs`：在沙箱里造四个 agent 的真实格式数据（来自 P0 的 fixture），启动真实 Electron，用 `MILE_WARP_AGENT_HOME` 指过去，断言：
  - 各 agent 的列表数量、标题、目录归类正确；`\\?\` 前缀的 Codex 目录能归到对应工作区。
  - 渲染层传文件路径或越界 ID 一律被拒。
  - 改名后再列出，标题变化；Claude 的原文件只多了追加行，没有其他改动。
  - 删除后文件进了回收站（沙箱里用测试开关改成移动到临时目录）、`sessionRecords` 里的对应记录被清掉。
  - 运行中会话的改名与删除被拒。
  - 导出的 Markdown、JSON、原文件内容正确。
  - Codex 写操作在数据库被占用时返回明确错误，不破坏数据库。
- 真实数据只读冒烟：对你本机真实目录跑一遍 `list`，要求 0 个解析异常崩溃，耗时在预算内（目标：1300 个线程加 400 个文件，首次列出 3 秒内，二次命中缓存 300 毫秒内）。写操作绝不在真实数据上跑自动测试。
- 沿用 `verify:ui` 扫描；`verify:all` 自动收录新脚本。

## 7. 对现有决策的影响

要写进 `decisions.md`：

1. **打破「只读 agent 自己的文件」原则**，范围限定为本功能：只改改名与删除，必须经过运行中检测、回收站、确认，且 Codex 写库单独授权。
2. 目录归属不依赖目录名反推（Claude 的编码不可逆），一律读文件内的 `cwd`。
3. 导出和删除的路径只在主进程出现，渲染层只有不透明 ID。

## 8. 不做的事

- **不做对话内容编辑。** 你说的「修改」我按「改标题、备注、标签」理解。改消息正文会破坏 Claude 的 `parentUuid` 链和 Codex 的 rollout 一致性，agent 续接时可能直接报错，收益也很小。
- 不做跨 agent 的会话转换（把 Claude 会话变成 Codex 会话）。
- 不做云同步。
- 不做会话内容的全文检索。第一版只搜标题和首条消息；全文要建索引，工作量和磁盘占用都大，放到以后。
- 不自动清理旧会话，只提供手动批量删除。

## 9. 需要你拍板的问题

1. **「修改」是不是只指改标题、备注、标签？** 我的建议是是，理由见 §8。
2. **允许直接写 Codex 的 sqlite 吗？** 不允许的话，Codex 只支持读取、导出、续接，改名只写别名层，删除只能由 Codex 自己处理。我建议先不允许，P4 单独评估。
3. **删除用回收站还是永久删除？** 我建议回收站，另给一个「永久删除」的二次确认选项。
4. **删除 Claude 会话时，要不要连带清理 `~/.claude/history.jsonl`（上下键输入历史）和附属目录？** 我建议默认不动输入历史，附属目录等 P0 核实对应关系后再定。
5. **「其他目录」（不属于任何工作区的会话）要不要显示？** 我建议显示，否则你在 Warp 外面开的会话管不到。
6. **是否要 P0 到 P2 先发版？** 我建议先发只读加导出版，再决定写操作做到哪一步。

## 10. 进度与 P0 实测结论（2026-11-01）

### 10.1 已完成（P0 到 P2，只读）

- 主进程：`services/SessionHistory.ts`（historyId 映射、预览分页、导出、realpath 校验）+ `services/history/{common,claude,codex,kimi,pi}.ts` 四个适配器；`shared/path.ts` 统一目录规范化（去 `\\?\`、斜杠、盘符大写）。
- IPC（四处同改）：`history:list / detail / export / reveal / resume`。渲染层只传 `historyId`，拿不到任何路径；`history:resume` 复用 `SessionService.start` 的 exact 续接。
- 界面：`components/HistoryDialog.tsx`（左目录、中列表、右预览；搜索、agent 筛选、显示工具调用、导出菜单、复制 ID、在资源管理器显示）。入口：标题栏按钮、`Ctrl+Shift+H`、命令面板「会话历史…」、工作区右键「历史会话…」（定位到该目录）。没有对应工作区时确认后新建一个（未分组）再续接。
- 验证：`scripts/verify-history.cjs` 63 项（沙箱造四种真实格式，覆盖列表、预览、越界、导出、续接、界面）。真实数据只读冒烟：1606 段（Claude 349、Codex 1224、Kimi 29、Pi 4），首次列出 0.7 秒，二次 43 毫秒，0 个读取失败。
- 开发期变量 `MILE_WARP_TEST_SAVE`：harness 用它跳过系统保存对话框，打包后不认。
