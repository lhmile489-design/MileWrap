## 1. 总体架构

沿用 Mile Terminal 的分层与纪律：**主进程拥有全部特权，渲染层没有任何特权**，两侧只通过 preload 白名单里的 IPC 频道通信。

```
┌──────────────────────────── Electron 主进程 ────────────────────────────┐
│  index.ts      窗口 / 托盘 / 快捷键 / IPC 注册与入参校形（sanitize*）      │
│  services/     ConfigStore  WorkspaceService  SessionService  AgentService │
│  lib/          argTokenizer  shimParser  atomicWrite  outputText          │
│  platform/     平台适配（首版只有 win32，接口保留 darwin 位）              │
└───────────────┬──────────────────────────────────────────────────────────┘
                │ contextBridge + ipcRenderer（白名单）
┌───────────────┴──────────────────────────────────────────────────────────┐
│ preload/index.ts  →  window.warp.*                                       │
├──────────────────────────────────────────────────────────────────────────┤
│ 渲染进程  React 19 + zustand + Tailwind 4                                │
│  App → TitleBar / SessionRail / FileRail / Console(宫格) / 弹窗 │
│  terminal/TerminalRegistry：每个会话一个 xterm 实例，按屏挂载              │
└──────────────────────────────────────────────────────────────────────────┘
```

- `src/shared/` 放两侧共用的类型、IPC 频道常量、默认值。
- 平台差异只在 `src/main/platform/`（默认 shell 探测、`taskkill`、外部终端拉起），服务层通过接口调用。
- 服务用构造函数注入依赖，不做全局单例。

## 4. 数据模型

配置落在 `%APPDATA%/mile-warp/config.json`，UTF-8 无 BOM，原子写，`.bak` 保留上一份良好版本，带 `CONFIG_VERSION` 显式迁移分支（照抄 Mile Terminal 的 `ConfigStore` 纪律，迁移不要用对象展开铺开默认值，否则 `version` 永远停在旧值）。

```ts
type Config = {
  version: number
  groups: Group[]
  workspaces: Workspace[]
  customAgents: AgentDef[]
  settings: Settings
  sessionRecords: SessionRecord[]   // 最近 50 条，供一键恢复
}

type Group = {
  id: string
  name: string
  color: string | null      // W-13，首版可为 null
  collapsed: boolean
  order: number
}

type Workspace = {
  id: string
  groupId: string | null    // null = 未分组
  name: string              // 显示名称，用户可改
  note: string              // 备注
  agentId: string           // 'claude' | 'codex' | 'kimi' | 'shell' | customAgent.id
  agentPath: string | null  // 覆盖自动探测的可执行文件（Q7）
  cwd: string               // 绝对路径，必须是真实存在的目录
  args: string[]            // 启动参数，已由 argTokenizer 切成数组
  envKeys: string[]         // 只给渲染层看键名
  order: number
  createdAt: number
  updatedAt: number
}

type AgentDef = {
  id: string
  name: string
  command: string           // 'claude' | 'codex' | 'kimi' | 自定义
  builtin: boolean
  resume: ResumeSpec | null   // 内置 agent 有；自定义 agent 首版为 null，见 §5.8
}

type ResumeSpec = {
  assignIdArgs: string[] | null     // 启动时指定会话 ID 的参数模板，如 ['--session-id', '{id}']；不支持则 null
  resumeArgs: string[]              // 按 ID 续接，如 ['--resume', '{id}']
  continueArgs: string[]            // 拿不到 ID 时的兜底，如 ['--continue']
  discover: 'none' | 'codex-rollout' | 'kimi-index'  // 事后发现 ID 的方式
}

type Settings = {
  theme: 'light' | 'dark' | 'system'
  shellPath: string | null      // null = 自动探测
  fontSize: number              // 默认 13
  fontFamily: string            // 默认 Cascadia Mono, Consolas
  scrollback: number            // 默认 5000
  copyOnSelect: boolean         // 默认 true
  keepShellOnAgentExit: boolean // 默认 false，见 §5.1
  restoreOnStartup: boolean     // 默认 false（手动点「一键恢复」），见 §5.7
  resumeConversation: boolean   // 默认 true：恢复时让 agent 续接上次对话；false 则只重新启动，见 §5.8
  closeAction: 'ask' | 'tray' | 'quit'  // 关闭窗口时记住用户上次的选择，默认 'ask'
}

type LayoutState = {            // 纯展示偏好，独立文件 window-state.json（代码里叫 Layout，见 shared/types.ts）
  width: number; height: number; x: number | null; y: number | null  // 只由主进程写；位置不在任何屏幕上时不沿用
  maximized: boolean            // 最大化时只记标志，不覆盖还原尺寸
  sessionRailWidth: number      // 会话栏宽度，默认 200，范围 160–320
  sessionRailCollapsed: boolean // 折叠为 56px 图标栏
  fileRailWidth: number         // 目录栏宽度，默认 240，范围 180–400
  fileRailVisible: boolean      // 用户手动显隐；宽度不足时的自动收起不改这个值
  gridMode: 'single' | 'dual' | 'quad'
  /** 四个格的会话 id；null = 空格。dual 只用 cell0 / cell1 */
  cells: [string | null, string | null, string | null, string | null]
  splitRatioH: number           // 双格左右比例，0.2–0.8
  splitRatioV: number           // 四宫格上下比例，0.2–0.8
}

/** 会话快照：只用于「下次启动一键恢复」，不代表进程可恢复 */
type SessionRecord = {
  id: string
  workspaceId: string
  agentId: string
  cwd: string
  args: string[]
  title: string
  cell: number | null           // 0–3，上次所在的格
  lastStartedAt: number
  lastExitCode: number | null
  resumeId: string | null       // agent 自己的会话 ID（Claude 自生成，Codex / Kimi 事后发现），见 §5.8
  resumeMode: 'exact' | 'continue' | 'fresh'  // 这次启动是续接、兜底续接还是新开
  kind: 'agent' | 'shell'       // M4 新增：「在此目录打开 Shell」的会话恢复为 Shell，不续接
  open: boolean                 // M4 新增：用户没手动关闭；应用退出 / 崩溃时保持 true，下次启动即为恢复候选
}
```

**环境变量的值不落明文**：写入时经 `safeStorage.encryptString` 转 base64 存进 `envEnc` 字段；`workspace:list` 返回 `envKeys` 而非 `env`；渲染层编辑时发合并补丁（字符串 = 新增或覆盖，`null` = 删除），与 Mile Terminal 的 `EntryEdit.env` 语义一致。

**会话进程不持久化，会话快照要持久化**：`SessionMeta`（id、workspaceId、status、pid、startedAt、exitCode、cols、rows）只活在主进程内存里；应用重启后进程必然消失。但每次会话启动、退出、用户退出应用时，把 `SessionRecord` 写入 `config.json` 的 `sessionRecords`（保留最近 50 条），用于下次启动的「一键恢复」：按记录里的工作区、agent、目录、参数和 `resumeId` 重新启动并**续接上次的对话**（见 §5.8），按 `cell` 还原到对应格。

格与格内会话的对应关系存在 `window-state.json` 的 `layout.cells` 里，不放渲染层 `localStorage`——这样主进程退出时能把「上次各格是什么会话」和快照一起写稳，渲染层崩溃也不丢。

**目录栏**只读：`fs:listDir` 每次读一个目录层级（懒加载），路径必须经 `realpath` 后仍在工作区目录内，符号链接跳出目录时不展开。不做 `fs.watch` 轮询；目录栏头部显示「有更新」由 agent 会话的输出里出现 `file://` 或文件写入事件时触发（M4 可选），首版只提供手动刷新。

## 5. 会话与进程

### 5.1 启动方式：直接启动 agent（对应 PRD Q6）

不先开 shell 再 `cd` 进去执行，而是把 agent 本身作为 PTY 的进程启动：

```
node-pty.spawn(file, args, { name: 'xterm-256color', cols, rows, cwd, env, useConpty: true })
```

理由：

1. agent 退出即会话结束，`onExit` 拿到的退出码就是 agent 的退出码，状态「已退出（含退出码）」才准确。若套一层 PowerShell，agent 退出后 shell 还活着，退出状态无法直接观测。
2. 不经过 shell 解析，没有引号转义与注入面（与 Mile Terminal 红线 3 同一条纪律）。
3. 输出直接是 agent 的输出，没有 shell 提示符与 `chcp` 之类的前置噪音。

代价与补偿：退出后没有 shell 可继续用。因此终端底部提供两个按钮（T-15）：「重新启动」与「在此目录打开 Shell」。原计划的 `keepShellOnAgentExit`（经 `cmd /d /s /c` 启动并保留会话）不做，理由见 decisions 2026-11-01「不做 keepShellOnAgentExit」；字段保留在 `Settings` 里只为兼容。

`cwd` 必须在主进程校验：绝对路径、`fs.statSync().isDirectory()` 为真，否则拒绝启动并给出可读错误。

### 5.2 命令解析与 `.cmd` 批处理壳

`node-pty` 在 Windows 上最终走 `CreateProcess`，**不能直接执行 `.cmd` / `.bat`**。实测本机 `codex` 只有 `C:\nvm4w\nodejs\codex.cmd`。

解析顺序（`AgentService.resolve`）：

1. `agentPath` 有值 → 直接用，仍要求存在。
2. 按 `PATH` 目录顺序，对每个目录按 `PATHEXT` 顺序（`.COM;.EXE;.BAT;.CMD`）找同名文件，**每个目录先看扩展名优先级**——这与 PowerShell 的解析顺序一致，因此 `claude` 会命中 `nvm4w\nodejs\claude.cmd`（PRD Q7 的默认行为）。
3. 拿到 `.exe` / `.com` → 直接 `spawn(file, args)`。
4. 拿到 `.cmd` / `.bat` → 先解析 shim（`shimParser`），能还原出真实目标就绕过批处理：
   - 匹配 npm cmd-shim 模板里的 `"%_prog%" "%dp0%\...\x.js"` → 启动 `node.exe` + 该 js，参数原样追加。
   - 匹配 `"%dp0%\...\x.exe"`（`claude.cmd` 就是这种）→ 直接启动那个 exe。
   - 都不匹配 → 退回 `cmd.exe /d /s /c "<file> <args...>"`。命令行由 `commandResolver.spawnArgs()` 拼成字符串交给 node-pty：每个参数按 CommandLineToArgvW 规则加引号后，cmd 元字符加 `^`，参数转两遍（cmd 一次、批处理 `%*` 一次），壳路径转一遍。node-pty 自己的数组转义不处理 `& | % ^`，不能依赖（见 decisions 2026-11-01、`verify-cmd-wrap.cjs`）。
5. 找不到 → 该预设标记为未安装，下拉置灰（A-02）。

**为什么要绕过批处理**：批处理在 Ctrl+C 时会弹 `Terminate batch job (Y/N)?`，而且 cmd 会再解释一遍 `&` `|` `%` 等字符。`codex.cmd` 里那句 `endLocal & goto #_undefined_# 2>NUL || ...` 就是 npm cmd-shim 用来规避这个提示的技巧，但 `claude.cmd` 没有这层保护。绕过批处理同时解决 Ctrl+C 与参数二次解释两个问题。

参数一律经 `argTokenizer` 从用户输入的字符串切成数组（支持双引号包裹、反斜杠转义），**永不拼接 shell 字符串**。

### 5.3 环境变量与编码

```
env = {
  ...process.env,                       // 继承 PATH（含 nvm / .local/bin / kimi-code/bin）
  ...decryptedWorkspaceEnv,
  TERM: 'xterm-256color',
  COLORTERM: 'truecolor',
  PYTHONUTF8: '1',
  PYTHONIOENCODING: 'utf-8'
}
```

- **删掉 `ELECTRON_RUN_AS_NODE`** 等 Electron 注入变量，避免影响子进程（照 Mile Terminal 的做法）。
- 不设 `FORCE_COLOR`：部分 agent 检测到它会改变配色或禁用 TTY 判断，交给 PTY 自己判断即可（Mile Terminal 设了 `FORCE_COLOR=1`，本项目改为不设，理由见 decisions.md）。
- **编码**：直接启动时不经 PowerShell，`chcp 65001` 那条前置指令不适用。ConPTY 的输出对 node-pty 永远是 UTF-8，agent 若用 `WriteConsoleW` 写宽字符（Node、Rust、Python 3 在 Windows 控制台下的默认行为）中文不会乱码。**风险项**：Python 版 `kimi.exe` 的控制台编码行为未实测，列入 M0 验证清单（用中文提示词跑一次 Kimi，检查输出）。

**M0 实测（2026-11-01，`scripts/verify-m0-pty.cjs`，Electron 43 主进程内）**：

- node 直接输出中文与中文路径、Windows PowerShell 5.1 输出中文，均正确，**不需要 `chcp 65001`**。
- `kimi --version` 经 PTY 正常；Kimi 对话里的中文输出需要真实发消息（消耗用户额度），探针没做，改在 M1 真实界面里人工验一次。
- `resize` 能同步到 ConPTY 与子进程；但 Node 子进程的 `'resize'` 事件在 ConPTY 下不一定触发，判断尺寸要读 `process.stdout.columns`，不要依赖事件。

### 5.4 输出缓冲与刷新

- 每个会话一个环形缓冲，上限 400 000 字符，供「重新挂载时回放」使用。
- 输出按 **16ms 合并**后推给渲染层（`session:data`），与 Mile Terminal 的 `FLUSH_INTERVAL_MS` 一致。
- 退出事件不保证晚于最后一块输出，**收尾要延迟**（`scheduleFinalFlush`，50ms 后补发一次）。

### 5.5 尺寸同步

- 渲染层 `ResizeObserver` → `fit.fit()` → `session.resize(id, cols, rows)`。
- 主进程侧做 50ms 去抖，`cols >= 2 && rows >= 2` 才下发，避免拖动分隔条时刷屏 `SIGWINCH`。
- 后台会话（不在任何格里显示）不 resize：切回可见格时先 `fit` 再 `resize`，让 TUI 自己重绘。

### 5.6 进程清理

- `session:kill` → `pty.kill()`，随后 **`taskkill /PID <pid> /T /F`**（`execFile` 数组形式，不拼字符串）。`pty.kill()` 在 ConPTY 下只关掉伪终端，agent 拉起的子进程（MCP server、`node` 子进程）可能残留。
- 「全部结束并退出」：`sessions.disposeAll()`（每个 `taskkill` 返回才 resolve，6 秒上限）再 `app.quit()`。
- 单实例锁：只在 `app.isPackaged` 下启用（同 Mile Terminal，避免开发期与 harness 互挤）。第二个实例启动时把第一个实例的窗口带回前台。

### 5.7 关闭、托盘与一键恢复

**关闭窗口**（`window:close` 或系统关闭按钮）不再直接退出：

1. 无运行中会话 → 直接退出。
2. 有运行中会话 → 渲染层弹确认框，两个动作：
   - `app:minimizeToTray`：`win.hide()`，会话继续运行；托盘图标切换为「运行中」样式。
   - `app:quitAll`：`disposeAll()` 后退出。
3. 两种动作都会先写 `sessionRecords` 快照（谁、哪个工作区、哪个 agent、哪个目录、哪个格、是否仍在运行）。

**托盘**（`TrayService`）：

- 菜单：显示主窗口 / 运行中的会话（子菜单，点击直接切到该会话所在格）/ 全部结束并退出。
- 双击托盘图标恢复窗口。
- 托盘存在期间 `app` 不退出；`window-all-closed` 不调用 `app.quit()`。
- 托盘图标两套：`resources/tray.ico`（空闲）与 `resources/tray-active.ico`（有运行中会话）；数字角标列 P2，首版用 tooltip 文字说明会话数。

**一键恢复**：

- 启动时 `SessionService.restoreCandidates()` 读 `config.json` 的 `sessionRecords`，过滤掉工作区已被删除、目录已不存在的记录，返回可恢复列表。
- 渲染层在控制台空态显示恢复卡片（逐个可取消勾选、可改成新开），点击后逐条 `session:restore({ recordId, cell, resume })`；`resume` 缺省时按 `settings.resumeConversation` 与候选的 `canResume` 决定。
- 主进程重新解析 agent 路径（`AgentService.resolve`），目录不存在则跳过并在结果里返回原因，**不回退到别的目录**。
- 恢复 = 重新启动进程 + 让 agent 续接上次的对话（§5.8）：应用不重放历史输出，不沿用旧 pid；终端画面由 agent 续接后自己重绘。新会话的 `SessionRecord` 以新 id 覆盖旧记录，`resumeId` 沿用。
- `settings.restoreOnStartup = true` 时启动即自动恢复，且只恢复 `lastExitCode === null`（上次未正常退出）的记录，避免把用户主动关掉的会话又拉起来；自动恢复同样按 §5.8 续接。

### 5.8 会话续接（resume）

「一键恢复」的目标是接着上次的对话继续，不是开一个全新对话。三个内置 agent 都支持按会话 ID 续接，但**拿到 ID 的方式不同**，下表是 2026-10-31 在本机实测 `--help` 与会话目录得到的结论：

| Agent | 启动时能否指定 ID | 续接命令 | 拿 ID 的办法 | 兜底（拿不到 ID） |
| --- | --- | --- | --- | --- |
| Claude Code | 能：`--session-id <uuid>` | `claude --resume <uuid>` | **不用找**：主进程用 `crypto.randomUUID()` 生成，启动时直接传入并写入快照 | `claude --continue` |
| Codex CLI | 不能 | `codex resume <uuid>`（`resume` 是子命令） | 启动后监视 `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，取启动之后新建、且首行 `session_meta.payload.cwd` 等于工作区目录的那个文件，读 `payload.id` | `codex resume --last`（默认按当前目录过滤） |
| Kimi Code | 不能 | `kimi --session <session_xxx>` | 启动前后各读一次 `~/.kimi-code/session_index.jsonl`，取新增行中 `workDir` 等于工作区目录（斜杠统一后比较）的那行，读 `sessionId` | `kimi --continue` |
| Pi | 能：`--session-id <uuid>`（不存在就按该 ID 新建，已存在就续接） | `pi --session-id <uuid>` | **不用找**：与 Claude 相同，主进程生成 UUID 并写入快照；用户自己写了 `--session` / `--resume` / `--continue` / `--fork` / `--no-session` 等参数时不再替它指定 | `pi --continue` |
| Shell / 自定义 | — | 不续接 | — | 重新开一个新会话（自定义 agent 的续接参数模板列 P2） |

规则：

1. **ID 一拿到就立刻写进 `SessionRecord.resumeId`**，不等退出。应用崩溃或被强杀时，快照里仍有 ID。
2. **同一目录开多个会话时，只认自己的 ID**。Claude 因为是自己指定所以没有歧义；Codex / Kimi 靠「启动之后新增」匹配，所以同一 `(agent, 目录)` 的会话**逐个启动**：等上一个拿到 ID 或超时（5 秒）再启动下一个。超时则该会话的 `resumeId` 留空。
3. **兜底只在不会串对话时使用**：`resumeId` 为空时，只有当快照里同一 `(agent, 目录)` 仅有这一条记录，才用 `--continue` / `--last`；有多条则这条改为新开，并在恢复卡片上标「新开（未能获取会话 ID）」，不静默用 `--continue` 让两个会话挤到同一段对话上。
4. **续接的目标不存在时**（用户清理过 agent 的历史、换了机器）：agent 自己会报错并退出。恢复卡片的「续接」只是尝试；会话退出条里的「重新启动」始终是新开，用户可以手动重来。
5. 工作区自己的 `args` 照常保留，追加在续接参数之后。Codex 的 `resume` 是子命令，所以实际形态是 `codex resume <uuid> <工作区 args>`；与 `--dangerously-bypass-approvals-and-sandbox`、`--model` 这类全局参数的相容性在 M0 实测。
6. ID 进入命令行前用 `/^[A-Za-z0-9_-]{8,64}$/` 校验，不合法的丢弃（仍是数组传参，没有注入面，校验是为了不让坏数据把 agent 带进异常状态）。
7. 恢复卡片每行显示「续接」或「新开」标记，用户可以逐条取消或把某条改成新开。

**M0 实测结论（2026-11-01）**：

| Agent | 结论 | 依据 |
| --- | --- | --- |
| Kimi | **启动即追加** `session_index.jsonl` 一行，不用等发消息 | 探针在临时目录启动 `kimi`，不发消息，9 秒内新增 1 行 |
| Codex | **首条消息后才创建** rollout | 探针在临时目录启动，代选 hooks 弹窗的「Continue without trusting」后进入主界面，空等 20 秒没有新 rollout 文件；本机最近 8 个历史 rollout 文件，创建时间都只比首条用户消息早 1.2–7.4 秒，佐证同一结论 |

据此规则 1、2 对 Codex 调整为：**会话期间持续监视**（不设 5 秒超时），监视到属于本会话的新 rollout 即写入 `resumeId`；同一 `(codex, 目录)` 的会话改为「谁的首条消息先到谁先认领」，按会话启动先后匹配新文件，仍有歧义时该条不写 ID、恢复时按规则 3 标「新开」。Kimi 维持原规则（启动前后比对、5 秒超时）。

另外：Codex 在一个新目录首次启动会弹「hooks 信任」确认框，这是 Codex 自己的交互，Mile Warp 不代答，用户在终端里选即可。

## 6. 终端渲染层

### 6.1 宫格布局

- `GridLayout` 组件按 `gridMode` 渲染：`single` 一格；`dual` 两列（`splitRatioH`）；`quad` 2×2（`splitRatioH` / `splitRatioV`）。分隔条统一是 `Splitter` 组件，拖动只改比例，不改 DOM 结构。
- 每格是一个 `TerminalPane`，通过 `cells[i]` 绑定会话 id；空格显示空态（含恢复卡片入口）。
- 切换 `gridMode` 不销毁任何会话：`dual → single` 时 `cell1` 的会话转入后台，`cells` 里保留它的 id，切回 `dual` 自动恢复显示。
- 拖拽换格：会话栏卡片或格头可拖，落到某格即交换 `cells[i]` 与 `cells[j]`，对应 xterm 容器跟着换父节点。
- 栏位：`SessionRail`（会话栏）与 `FileRail`（目录栏）用 `Splitter` 与控制台分隔；控制台可用宽度 < 744px 时按 UI 文档 §3 临时收起目录栏，不改 `fileRailVisible`。

### 6.2 会话保活与重新挂载

格内切换会话时**不销毁 xterm 实例**，这是保证 TUI（全屏 alternate screen、光标定位）切回来画面正确的关键：

- `TerminalRegistry` 持有 `sessionId → { term, fit, containerEl, webgl }`。
- 不可见的会话：容器 `display: none` 留在隐藏池里，`term.write` 照常写入（xterm 在不可见时跳过渲染，解析仍进行）。
- 挂载：把 `containerEl` 直接挪进目标格的宿主节点。xterm 6 支持把 `term.element` 重新挂到新父节点，不需要 `open()` 第二次。
- WebGL 上下文数量有上限（Chromium 单页约 16 个），**只给当前可见的格加载 `WebglAddon`**（最多 4 个），隐藏时 `dispose()` 该插件、显示时重新加载；加载失败（驱动不支持）回落到 DOM 渲染器。
- 若重新挂载后画面错位，退路是「主进程用 `@xterm/headless` + `@xterm/addon-serialize` 维护快照，渲染层重开时 `term.reset()` 后写入快照」；这条退路不引入，先按上面的方案做，M0 实测。

### 6.3 按键拦截

`attachCustomKeyEventHandler` 的规则（T-18）：

| 组合 | 行为 |
| --- | --- |
| `Ctrl+Shift+C` / `Ctrl+Shift+V` | 复制 / 粘贴，返回 `false` |
| `Ctrl+Shift+F` | 打开搜索条 |
| `Ctrl+=` / `Ctrl+-` / `Ctrl+0` | 字号加减复位（只在应用内，不改终端内 agent 的按键语义） |
| `Ctrl+Tab` | 焦点在可见格之间切换 |
| `Ctrl+Shift+1`–`4` | 焦点直接切到第 N 格 |
| 其余（含 `Ctrl+K`、`Esc`、方向键） | 返回 `true`，原样交给 agent |

`Ctrl+C` 有选区时按 Windows Terminal 的惯例先复制再清选区，**不向 agent 发送 `\x03`**；无选区时照常发送中断（PRD T-07）。

### 6.4 目录栏

- `FileTree` 组件：每层 `fs:listDir({ workspaceId, relativePath })`，返回 `{ name, kind, size, mtime }[]`，目录优先、按名称排序（不区分大小写）。
- 展开时懒加载，已加载节点缓存 30 秒；头部「刷新」清空缓存重读。
- 主进程校验：`path.resolve(workspace.cwd, relativePath)` 经 `fs.realpath` 后必须以 `workspace.cwd` 为前缀（大小写不敏感比较，Windows 盘符统一大写），否则拒绝。
- 双击文件用系统默认程序打开？**不做**——目录栏只读，双击只展开/折叠目录，避免误开大文件。右键菜单提供「在资源管理器中显示」。

### 6.5 右键与粘贴

- 右键：有选区 → 复制；无选区 → 粘贴（与 Mile Terminal 一致）。
- 粘贴统一走 `navigator.clipboard.readText()`，再 `term.paste(text)`（自动处理 bracketed paste）。

## 8. 安全模型

渲染层没有任何特权，以下全部在主进程决定：

1. **可执行文件不可由渲染层指定**：`session:start` 只收 `workspaceId`，命令、参数、目录都从配置里取；配置里的 `cwd` 在保存时校验，`agentPath` 在探测时校验。
2. **参数不拼 shell 字符串**：一律数组；退回 `cmd.exe` 包装时仍走数组。
3. **env 值不出主进程**：只给键名；写盘加密（`safeStorage`）。
4. **目录校验**：`cwd` 必须绝对路径且 `isDirectory()`；`shell:openPath` / `openExternalTerminal` / `fs:listDir` / `fs:reveal` 只接受 `workspaceId` + 相对路径，绝对路径由主进程拼出来并 `realpath` 校验仍在工作区目录内，越界、不存在、符号链接跳出目录一律拒绝、不回退。
5. **外部终端**：Windows 下经 `cmd /d /c start "" wt.exe -d .` 拉起（`wt.exe` 是应用执行别名，`existsSync` 认不出，用 `lstat`）；目录只走 `cwd` 选项或 `-d .`，**不进命令行**（wt 把 `;` 当子命令分隔符）。
6. **IPC 只认主窗口主框架**（`isTrustedSender` 包装器）。
7. **`window.open` 拦截**：`setWindowOpenHandler` 一律 `deny`，外链走 `shell:openUrl`。

## 9. 主进程服务职责

| 服务 | 职责 | 红线 |
| --- | --- | --- |
| `ConfigStore` | 读写、版本迁移、`.bak` 轮转、原子写、env 加解密 | 写坏了不能牵连 `.bak`（坏主文件另存 `config.json.corrupt`） |
| `WorkspaceService` | 分组与工作区 CRUD、排序、移动到分组、校验 | 名称 ≤ 80 字符；`cwd` 必须存在 |
| `AgentService` | 预设、PATH 解析、`.cmd` shim 解析、版本探测（`--version`，5 秒超时，启动后异步执行并缓存） | 探测只执行 agent 自己的 `--version`，不执行项目代码 |
| `SessionService` | `node-pty` 会话、16ms 合并、环形缓冲、退出清理、`taskkill` 树终止、会话快照与恢复 | 永不把渲染层入参直接交给 `spawn` |
| `FileTreeService` | 目录懒加载、排序、缓存、`realpath` 越界校验 | 只读；不做写入、删除、重命名 |
| `GitInfoService` | 读 `.git/HEAD` 得到分支名；`.git` 是文件（worktree / submodule）时跟随 `gitdir:` 指针 | 只读文件，不执行 `git`，不碰项目 hooks |
| `GitService` | Git 管理（Git管理-PRD）：按 workspaceId 求仓库根，执行 status / 暂存 / diff / 丢弃 / 提交（simple-git） | `settings.gitEnabled` 为 false 时不执行任何 git；固定 `-c core.fsmonitor=false`，diff 加 `--no-ext-diff --no-textconv`；丢弃只认一次性 token；参数数组、环境清洗、超时；不返回绝对路径 |
| `TrayService` | 托盘图标、菜单、窗口显示/隐藏、会话数角标 | 菜单里的结束操作只调 `SessionService`，不另开命令通道 |

## 10. 验证方式

沿用 Mile Terminal 的「真实进程 harness」纪律，不引入单元测试框架：

- `scripts/verify-*.cjs`：启动真实 Electron 主进程、加载 `out/` 产物、`executeJavaScript` 驱动真实渲染层，断言读 `getComputedStyle` / `getBoundingClientRect` / IPC 回执，不靠截图。
- **harness 必须在 `require` 主进程包之前 `app.setPath('appData', tmpdir)`**，否则写的是真实配置。
- 关键不变量：
  - `verify-m0-pty.cjs`：三种 agent 的解析路径与 `.cmd` shim 还原（纯逻辑，喂真实 `where` 输出与真实 shim 文本）。
  - `verify-m1-session.cjs`：启动 → 写入 → 输出 → 退出码 → `taskkill` 后进程树为空。
  - `verify-m3-grid.cjs`：四宫格各跑一个会话，切换布局后会话不丢失、`session:buffer` 回放内容完整、每格 `cols` 不同且 PTY 收到对应尺寸。
  - `verify-m4-restore.cjs`（原计划名 `verify-m3-restore`，随 M4 落地改名）：编排进程连续起 3 次真实应用，共用沙箱 appData；agent 用沙箱里的假 agent（npm cmd-shim 格式 `.cmd` + node 脚本，把参数写到文件），`MILE_WARP_AGENT_HOME` 把 `~/.codex`、`~/.kimi-code` 指到沙箱。覆盖：续接 ID 获取（Claude 自生成、单个 Codex 认领 rollout、同目录两个 Codex 有歧义不写、同目录两个 Kimi 排队各拿各的）；关闭确认框（取消 / 托盘 / 记住后全部结束）；退出期间退出码不写快照；目录被删的记录被过滤；`--resume` / `resume <id>` / `--session <id>` 实际传给进程；`canResume=false` 新开；放回原格；忽略；S-10 续接启动；启动时自动恢复只拉起没正常退出的。
  - `verify-m2-rail.cjs`：坏主文件从 `.bak` 恢复并另存 `.corrupt`；分组新建 / 行内改名 / 折叠落盘；筛选；组内排序、跨组移动、分组排序（合成 DragEvent）；编辑弹窗与环境变量（不明文落盘、会话里可读）；多会话子行与改名；删除确认；目录栏懒加载、刷新、方向键；焦点在终端里时栏位快捷键生效且不进 PTY。
  - `verify-fs-guard.cjs`：`fs:listDir` 传 `..\..`、绝对路径、符号链接跳出目录，全部拒绝。
  - `verify-ui.cjs`（`node` 直接跑，不需要 build）：扫源码把关硬规则：文字色不加透明度、字号 ≥ 12px、不用任意值圆角、图标尺寸只用 12 / 16 / 20 / 24、不用原生 confirm / alert / prompt。
  - `verify-m5-settings.cjs`：默认应用菜单已去掉（`Ctrl+R` / `Ctrl+W` 进 PTY）；设置页各项立即生效并落盘、越界值被拒；默认 Shell 白名单；字号快捷键；命令面板；终端内搜索；标题栏主题菜单。
  - `verify-package.cjs`（`node` 跑，需要先 `npm run build:win`）：启动打包后的 exe（`MILE_WARP_DATA_DIR` 指到临时目录），经 CDP 确认 preload 在、node-pty 能从 `app.asar.unpacked` 加载并起 Shell 会话、单实例锁生效、真实配置目录没被碰。
- `npm run typecheck` 两套 tsconfig 必须都过；`npm run build` 零警告。
