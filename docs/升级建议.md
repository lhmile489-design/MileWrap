# Mile Warp 升级建议

> 日期：2026-11-01
> 依据：M0–M5 的实现现状（`CLAUDE.md` 各里程碑完成情况）、PRD 里还没做的 P1 / P2 项、`docs/踩坑记录.md` 里的未解决问题，以及「同时跑几个 agent」这个核心场景里还不顺手的地方。
> 这是建议清单，不是承诺。每条都写了改动范围和与现有决策的关系，可以逐条挑。

---

## 0. 怎么读这份文档

每条建议按同一个格式写：

- **现状**：现在的应用是什么样，哪里不够。
- **建议**：要做成什么样。
- **实现要点**：大致改哪些文件、要不要新 IPC。凡是新增能力，都要照 CLAUDE.md 的规则在 `shared/channels.ts`、主进程 `sanitize*`、preload、`index.d.ts` 四处同时改。
- **成本**：S = 半天以内，M = 1–2 天，L = 3 天以上。
- **注意**：与 `docs/decisions.md` 里现有决策的关系，以及需要守住的底线。

优先级分三档：

| 档位 | 含义 |
| --- | --- |
| 先修 | 影响稳定性或数据，建议排在任何新功能之前 |
| 第一批 | 价值高、成本低，直接改善「多 agent 并行」的日常体验 |
| 第二批 / 第三批 | 价值明确，但成本更高，或需要先确认产品方向 |

## 1. 先修：稳定性

### 1.1 退出时偶发崩溃 / 残留 agent 进程

- **现状**：`踩坑记录.md` 最后一条记着：`verify-m4-restore.cjs` 连跑 8 次有 2 次失败。一次是「全部结束并退出」时进程以 `0xC0000005` 崩溃；另一次是退出后残留了 1 个 agent 进程。目前原因不明。
- **建议**：
  1. 先加主进程日志（见 1.2），记下 `shutdown → killEntry × N → tray.destroy → app.quit` 每一步的时间点，以及有没有超时。
  2. 退出顺序改成：所有会话的 `onExit` 都到了（或者超时）之后，才 `tray.destroy()` 和 `app.quit()`。超时的会话按 pid 再补一次 `taskkill /T /F`。
  3. 启动时做一次孤儿清理：把运行中会话的 pid 和启动时间写进快照。下次启动时，如果发现这些 pid 还活着，并且进程命令行与记录一致，就在界面上提示「上次有 N 个 agent 进程没结束」，由用户确认后再结束它们。
- **实现要点**：`SessionService.shutdown`、`index.ts` 的 `quitAll`；`SessionRecord` 增加 `pid`；查进程命令行用 `Get-CimInstance Win32_Process`，注意用数组参数调用 `execFile`。
- **成本**：M。
- **注意**：孤儿清理绝不能自动杀进程，因为 pid 会被系统复用。必须同时满足「pid 与命令行都匹配」和「用户确认」两个条件。

### 1.2 主进程日志

- **现状**：出问题时只能看 harness 的输出，用户机器上什么都留不下来。
- **建议**：在 `%APPDATA%\mile-warp\logs\` 下写按天滚动的日志，最多保留 7 天。记录会话的启动、退出、退出码，续接 ID 的获取结果，IPC 校形被拒的次数（只记频道名和原因，不记参数值），以及关闭流程的时序。设置 → 关于页加「打开日志目录」按钮。
- **实现要点**：新增 `main/lib/log.ts`，用 `appendFile` 加按日期切分文件。
- **成本**：S。
- **注意**：不能写进环境变量的值、终端输出内容、剪贴板内容；路径可以写。

### 1.3 渲染进程崩溃自动恢复

- **现状**：渲染进程崩溃（`render-process-gone`）后，窗口会白屏。会话其实还在主进程里运行，主进程也有 400k 字符的回放缓冲，但没有任何地方会触发重新加载。
- **建议**：监听 `render-process-gone`，自动 `reload()`。布局和格位已经存在 `window-state.json` 里，终端画面由 `session:buffer` 回放，`verify-m3-grid.cjs` 第 10 步已经覆盖了这条路径。如果 1 分钟内连续崩溃 3 次，就停止自动重载，改为显示错误页，提供「重新加载」按钮。
- **成本**：S。

## 2. 第一批：让多 agent 并行更省心

这一批解决的核心问题是：开了 3–4 个 agent，用户不知道哪个跑完了、哪个在等自己回答。现在只能逐格去看。

### 2.1 会话「有新输出 / 安静了」指示

- **现状**：会话卡片只显示「运行中」，看不出 agent 是在跑任务，还是已经停下来等输入。后台会话和非聚焦格尤其如此。
- **建议**：完全按输出活动判断，不解析输出内容：
  - **活跃**：最近 3 秒内有输出。状态方块的呼吸动画加快，或者换成转圈图标。
  - **安静**：先连续输出超过 10 秒，然后安静超过 5 秒。这通常意味着 agent 跑完了一轮，在等输入。卡片右侧出现一个强调色小点，格头标题旁边也出现同样的点。
  - 用户切到这个会话（聚焦它所在的格）后，小点消失。
- **实现要点**：渲染层已经能收到每个会话的 `session:data`（`TerminalRegistry` 里有订阅），在那里按会话记录「最后输出时间」和「这一轮开始时间」，放进一个新的 store `store/activity.ts`。选择器只返回原始值（布尔或时间戳），避免 React #185 无限重渲染。
- **成本**：S–M。
- **注意**：PRD §7 写了「不解析 agent 的输出内容」。这里只看「有没有输出」和时间，不看输出是什么，没有越界。阈值放进设置里，因为不同 agent 的输出节奏不一样。

### 2.2 任务完成通知（PRD T-16）

- **建议**：后台会话或非聚焦格的会话进入「安静」状态、或者进程退出时：
  - 发一条 Windows 系统通知（Electron `Notification`），标题是会话名，正文是「看起来在等你」或「进程已退出，代码 N」。点通知就把窗口带到前台，并切到这个会话。
  - 窗口不在前台时，任务栏图标闪烁（`win.flashFrame(true)`），获得焦点后停止。
  - 设置 → 通知：可分别开关「等待输入」与「进程退出」两类，并设置免打扰时段。
- **实现要点**：通知必须由主进程发。可以新增频道 `notify:sessionIdle`，由渲染层上报；但更稳的做法是在主进程按输出时间自行判断，这样渲染层被节流或隐藏时也能工作。`SessionService.flush` 里已经有每块输出的时间点，可以直接用。
- **成本**：M。
- **注意**：窗口在前台、且这个会话就在聚焦格里时，不发通知。

### 2.3 任务栏数字角标

- **现状**：运行中的会话数只在托盘 tooltip 里能看到（数字角标被列为 P2）。
- **建议**：用 `win.setOverlayIcon()` 在任务栏图标右下角显示一个数字。显示「等你处理」的会话数，比显示运行中的会话总数更有用。数字图标在运行时用 `nativeImage` 画出来，和托盘绿点用同一套写法。
- **成本**：S。

### 2.4 目录栏：复制路径 / 发送路径到终端

- **现状**：目录栏的右键菜单只有「在资源管理器中显示」。用户想让 agent 看某个文件时，得自己手敲路径。
- **建议**：节点右键增加：
  - 复制相对路径、复制绝对路径；
  - **插入到当前终端**：把路径写进聚焦格 agent 的输入行。Claude Code 用 `@相对路径`，其他 agent 用相对路径；含空格时加引号。
  - 把文件从目录栏直接拖到终端格，效果同「插入到当前终端」。
- **实现要点**：插入走现有的 `session:write`，写的是文本，不带回车，不会替用户提交。相对路径在渲染层就有（`data-rel`），绝对路径要新增 `fs:resolve`，由主进程校验后返回。
- **成本**：S。
- **注意**：目录栏仍然只读（decisions「目录栏是只读目录树」）。这里只是复制和插入文本，不改文件。

### 2.5 从资源管理器拖文件夹新建工作区

- **现状**：新建工作区要点「选择」，再在系统对话框里找目录。
- **建议**：把文件夹从资源管理器拖到会话栏，就打开新建弹窗，目录与名称预先填好（名称取文件夹名，agent 取上次用的那个）。也支持在会话栏按 `Ctrl+V` 粘贴一个目录路径。
- **实现要点**：渲染层 `drop` 事件里拿到的 `File.path` 在沙箱下读不到，要用 preload 的 `webUtils.getPathForFile(file)` 取路径。拿到的路径只用来预填表单，最终校验仍由 `workspace:create` 的 `sanitizeCwd` 负责。
- **成本**：S。

### 2.6 终端里的文件路径可点击

- **现状**：只有 http / https 链接可以点。agent 输出里大量出现 `src/foo.ts:42` 这类路径，点不了。
- **建议**：给 xterm 注册一个链接识别器，匹配相对路径和 Windows 绝对路径（可带 `:行号`）。点击后用 VS Code 打开到对应行（本机装了 `code` 才显示这个选项），否则在资源管理器中显示。
- **实现要点**：xterm 的 `registerLinkProvider`。主进程新增 `fs:openInEditor({ workspaceId, relativePath, line })`：路径照 `FileTreeService.locate` 的规则校验，编辑器只认探测到的 `code` 命令，用数组参数启动。
- **成本**：M。
- **注意**：会打开的路径只限工作区目录之内，越界一律拒绝，规则与目录栏一致。

## 3. 第二批：工作流与效率

### 3.1 布局预设：一键开工

- **现状**：每天开工，都要手动在四格里各开一个工作区。一键恢复只能还原「上次退出时」的样子，不能保存一套固定的组合。
- **建议**：把当前的「宫格模式 + 每格对应哪个工作区」存成命名预设，比如「前端联调：四格 = 客户端 Claude / 服务端 Codex / 管理端 Claude / Shell」。在命令面板或标题栏里选一个预设，就切到那个宫格、在各格启动对应的工作区。已在运行的会话不重复开，直接放进对应的格。
- **实现要点**：预设存进 `config.json`（新字段 `layoutPresets`，`CONFIG_VERSION` 升到 2，并写显式迁移分支）；启动复用 `openWorkspace(w, cell)`。
- **成本**：M。

### 3.2 分组「全部启动 / 全部结束」

- **建议**：分组标签行的「⋯」菜单加两项：全部启动（按格依次放，放满后的转后台）、全部结束（先确认）。Mile Terminal 的工作组磁贴就有这个功能。
- **成本**：S。
- **注意**：同一目录有多个 Kimi 工作区时，主进程本来就会排队启动，不需要额外处理。

### 3.3 自定义 agent（PRD A-03，P1）

- **现状**：只有 4 个内置预设，Gemini CLI、Aider、OpenCode 这类 agent 只能用 Shell 工作区代替。
- **建议**：设置 → Agent 增加「添加 agent」：填名称、命令、默认参数、徽章颜色，可选填续接模板（`resumeArgs` / `continueArgs`，用 `{id}` 当占位符）。新增的 agent 会出现在工作区弹窗的下拉里。
- **实现要点**：`config.customAgents` 字段已经存在。`AgentService` 解析时合并自定义 agent。`WorkspaceService.sanitizeWorkspaceInput` 里的 agent 白名单改为「内置 + 自定义」。徽章颜色保存时校验前景对比度 ≥ 4.5:1（UI 设计约束 §4.3 已有规定）。
- **成本**：M–L。
- **注意**：命令只接受命令名，或者用系统文件对话框选出来的绝对路径，不接受渲染层任意拼出的命令行。参数照旧经 `argTokenizer` 切成数组。

### 3.4 广播输入（PRD T-17，P2）

- **建议**：标题栏加一个「广播」开关。打开后，在聚焦格里输入的内容会同时发给所有可见格。格头显示「广播中」胶囊，聚焦格的边框变成警示色。可以逐格排除。
- **成本**：M。
- **注意**：这个功能很容易误操作（例如对 4 个 agent 同时回答 y），所以默认关闭；每次打开都要确认一次，关窗口后自动关闭，不写进设置。

### 3.5 命令面板增强

- **最近使用**：最近打开过的 5 个工作区和会话，在不输入时排在最前面。
- **拼音首字母**：输入 `khd` 能搜到「客户端」。需要一张常用汉字到拼音首字母的表（约 20KB），按需加载。
- **命令带参数**：例如「在第 3 格打开 …」选了动作之后，再选工作区。
- **成本**：S + M + M。

### 3.6 快捷键速查与自定义

- **建议**：按 `Ctrl+/` 弹出快捷键速查浮层，内容与设置 → 关于页里的表一致。之后再考虑自定义快捷键：只允许改成 `Ctrl+Shift+` 组合，避免抢走 agent 的按键（PRD T-18）。
- **成本**：S（速查）/ M（自定义）。

### 3.7 目录栏「有更新」提示（PRD D-06 可选部分）

- **现状**：目录栏只能手动刷新（decisions「目录栏不做自动轮询」）。
- **建议**：只对**已展开**的目录层级做非递归的 `fs.watch`，有变化时在目录栏头部显示「有更新」小点，点一下再刷新。展开的层级通常只有十几个，不会碰到递归 watch 的句柄与性能问题。
- **成本**：M。
- **注意**：只提示、不自动重读；`node_modules` 这类灰化的目录不 watch。

### 3.8 git 改动标记（2026-11-05 已拍板，并入 Git 管理 G-18）

- **现状**：GitInfoService 只读 `.git/HEAD`，按规定不执行 `git`。
- **建议**：先讨论要不要放宽。如果放宽，就加一个设置项「显示 git 改动」，默认关闭；打开后在工作区目录里只读地运行 `git status --porcelain=v1 -z`（5 秒超时，结果缓存 10 秒），在目录栏给改过的文件标 M / A / ?。这能直接回答「agent 改了哪些文件」。
- **注意**：这和现有决策冲突（不执行 git、不碰项目 hooks）。`git status` 本身不触发 hooks，但会读仓库配置。
- **结论**（2026-11-05）：放宽，跟随设置「启用 Git 管理」总开关（默认关），实现见 `docs/Git管理-PRD.md` G-18，决策见 decisions.md 同日条目。

## 4. 第三批：终端与细节体验

| 编号 | 建议 | 说明 | 成本 |

| 4.2 | 长文本输入框 | 可选的输入框（默认关），用来写多行提示词，`Ctrl+Enter` 以 bracketed paste 发给 agent，保留最近 20 条历史。PRD Q10 当初因为「抢焦点」没做，做成按格手动打开、发完自动收起，就能避开这个问题 | M |

| 4.8 | 关闭单个格时问一下 | 多格模式下关掉的是还在运行的会话时，确认框里给「转入后台」选项，而不只有「结束」 | S |
